## Ажиллуулах

WSL2 Bash дээр `lab5/` хавтсаас API-г асаана. `server.js` нь Node.js-ийн стандарт санг ашигладаг.

```bash
node server.js
```

Postman-д `lab05-collection.json` импортлоод collection-ийн `baseUrl` нь `http://localhost:3000` байгааг шалгана. Кейс бүрийг setup-тай нь ажиллуулахын тулд Runner-аас бүтэн collection эсвэл тухайн кейсийн хавтсыг сонгоно.

Хоёр дахь Bash терминалд мөн `lab5/` хавтсаас доорх командуудыг ажиллуулна. WSL-д Newman суулгах шаардлагатай бол `npm install -g newman@6` ашиглана.

```bash
mkdir -p results
newman run lab05-collection.json --color off 2>&1 | tee results/newman-pass.txt
echo "exit=${PIPESTATUS[0]}"
newman run lab05-collection-fail.json --color off 2>&1 | tee results/newman-fail.txt
echo "exit=${PIPESTATUS[0]}"
```

Эхний терминалд `Ctrl+C` дарж API-г зогсоогоод DOWN шалгалт хийнэ.

```bash
newman run lab05-collection.json --color off 2>&1 | tee results/newman-down.txt
echo "exit=${PIPESTATUS[0]}"
```

`PIPESTATUS[0]` нь Newman-ийн exit code. Pipeline-ийн дараах эхний командаар авна. Дан `$?` нь ердийн Bash тохиргоонд `tee`-ийн кодыг өгнө.

## Тестийн дизайн

Тусад нь тестлэх функц нь `POST /registrations`. Тестийн сонголт, төлөөлөх утга, спецификацийг доор өгсөн. Спецификаци бүрийн ID Postman collection дахь хавтасны нэрийн эхэнд байна.

### Сонголт ба төлөөлөх утга

| Сонголт | Эквивалент анги | Төлөөлөх утга |
| --- | --- | --- |
| `studentID`-ийн хүчинтэй байдал | Идэвхтэй, идэвхгүй, байхгүй | `status: "active"`, `status: "inactive"`, үүсгээгүй оюутны ID |
| Оюутны үзсэн хичээл | Урьдач нөхцөлийг хангана, хангахгүй | Бүх шаардлагатай кодтой `coursesTaken`, хэсэгчилсэн жагсаалт, `[]` |
| `courseID`-ийн хүчинтэй байдал | Байгаа, байхгүй | PUT-аар үүсгэсэн ID, үүсгээгүй хичээлийн ID |
| Урьдач хичээлийн хамрагдалт | Бүгдийг үзсэн, огт үзээгүй, заримыг үзсэн, урьдачгүй | `prerequisites: ["CS201", "CS202"]`-ыг `["CS201", "CS202"]`, `[]`, `["CS201"]`-тай харьцуулах, эсвэл `prerequisites: []` |
| Хүсэлтийн формат | Хоёр ID байгаа, талбар дутуу, JSON буруу | Хоёр ID-тай JSON, зөвхөн `studentID`-тай JSON, хаагдаагүй JSON объект |

### Спецификаци

| ID | Төрөл | Setup ба POST оролт | HTTP | `result` | Нэмэлт oracle |
| --- | --- | --- | --- | --- | --- |
| C01 | Амжилттай | Идэвхтэй `B231234567` оюутан `CS201` үзсэн. `CS313` нь `CS201` шаарддаг | 201 | `OK` | Тоон `registrationID` |
| C02 | Оюутан байхгүй | Хичээл байгаа. Үүсгээгүй оюутны ID илгээнэ | 200 | `ERROR_NO_STUDENT` | |
| C03 | Оюутан идэвхгүй | Идэвхгүй оюутан урьдач хичээлээ үзсэн. Сонгосон хичээл байгаа | 200 | `ERROR_INACTIVE_STUDENT` | |
| C04 | Хичээл байхгүй | Идэвхтэй оюутан байгаа. Үүсгээгүй хичээлийн ID илгээнэ | 200 | `ERROR_NO_COURSE` | |
| C05 | Урьдач дутуу | Идэвхтэй оюутан `CS201` үзсэн. Хичээл `CS201`, `CS202` шаарддаг | 200 | `ERROR_PREREQUISITES` | `missing` яг `["CS202"]` |
| C06 | Давхар алдаа | Идэвхгүй оюутан ба үүсгээгүй хичээлийн ID | 200 | `ERROR_INACTIVE_STUDENT` | Идэвхийг хичээлийн оршин байхаас өмнө шалгана |
| C07 | Давхар алдаа | Идэвхгүй оюутны `coursesTaken: []`. Хичээл `CS201`, `CS202` шаарддаг | 200 | `ERROR_INACTIVE_STUDENT` | Идэвхийг урьдач хичээлээс өмнө шалгана |
| C08 | Хязгаар | Идэвхтэй оюутны `coursesTaken: []`, хичээлийн `prerequisites: []` | 201 | `OK` | Тоон `registrationID` |
| C09 | Хязгаар | Идэвхтэй оюутан ба хичээл байгаа. POST биед `studentID` илгээнэ | 400 | `ERROR_BAD_REQUEST` | |

Хавтас бүр өөрийн PUT хүсэлтээр шаардлагатай өгөгдлийг бүрдүүлээд POST-оо ажиллуулна. Байхгүй байх ёстой ID-уудыг ямар ч setup үүсгэдэггүй. PUT нь тухайн бичлэгийг бүтнээр нь шинэчилдэг. Амжилттай бүртгэлүүд нэг серверийн процесс дотор хуримтлагдах тул ID-ийн төрлийг шалгана.

## Newman-ийн бодит үр дүн

Үндсэн тестийн тоо **51 assertion**, `newman-pass.txt`-ийн `assertions executed` утгатай таарна. Нэг сервер дээр бүтэн collection-ийг дараалан хоёр удаа PASS ажиллуулсан. C01–C09 тус бүр цэвэр ассан сервер дээр өөрийн setup-тайгаа дангаар PASS болсон. Тусдаа smoke хүсэлтээр буруу JSON нь `400 ERROR_BAD_JSON` буцаасныг шалгасан.

| Ажиллуулалт | Iterations executed / failed | Requests executed / failed | Assertions executed / failed | Newman exit |
| --- | ---: | ---: | ---: | ---: |
| [PASS](results/newman-pass.txt) | 1 / 0 | 24 / 0 | 51 / 0 | 0 |
| [FAIL](results/newman-fail.txt) | 1 / 0 | 24 / 0 | 51 / 1 | 1 |
| [DOWN](results/newman-down.txt) | 1 / 0 | 24 / 24 | 51 / 51 | 1 |

FAIL нь тусдаа collection дахь C01-ийн статус oracle `200` хүлээхэд сервер `201` өгсөн зөрүү, DOWN нь серверийн хариу ирэхээс өмнө `ECONNREFUSED` гарсан интерфейсийн алдаа бөгөөд хариу байхгүйгээс oracle-ууд мөн унасан. `tee` гурван удаа `0` буцаасан. Newman-ийн exit `1`-ийг CI quality gate-д алдаа гэж үзнэ.

## Дүгнэлт

Таван алхмаас оролтын ангиудыг хослуулж спецификаци сонгох хэсэг хамгийн их бодол шаардсан. Оюутан байхгүй үед түүний идэвх болон үзсэн хичээлийг утгатайгаар сонгох боломжгүй. Хичээл байхгүй үед урьдач нөхцөлийн хамрагдалтыг тогтоох боломжгүй. C06, C07 нь идэвхийн шалгалт хичээлийн оршин байх болон урьдач нөхцөлийн шалгалтаас түрүүлдгийг бодит хариугаар харуулсан. C05-ийн `missing` шалгалт сервер зөвхөн дутуу хичээлийг буцаасныг баталсан. C08 нь хоосон хоёр жагсаалттай үед бүртгэл амжилттай болохыг харуулсан. Бүх хавтсыг тусад нь ажиллуулахад нэг кейсийн setup нөгөө кейст шаардлагагүй байв. Хамруулсан нөхцөлүүдэд API-ийн согог илрээгүй. FAIL ба DOWN ажиллуулалт нь буруу хүлээлт болон холболтын тасалдлыг автомат тест тус тус илрүүлж байгааг харуулсан.

## Нэмэлт ажил

### Нийтийн API

`newman run lab05-public-api.postman_collection.json` ажиллуулж [JSONPlaceholder-ийн `/users`](https://jsonplaceholder.typicode.com/users) хариу `200`, массив, эхний `name` нь `Leanne Graham` байгааг шалгасан. Нийтийн API-ийн GET нь setup шаардахгүй учраас оюутан, хичээл үүсгээд POST хийдэг локал кейсүүдээс бэлтгэхэд хялбар байв.

### AI-ийн саналтай харьцуулсан нь

> Энэ API-гийн POST /registrations функцийн сонголтуудыг тодорхойлж, сонголт бүрийг эквивалент ангид хуваагаад, ангиудын хослолоор Postman тестүүд үүсгэ.

AI-ийн эх кодоос гаргасан нэмэлт саналд хүчинтэй, талбар дутуу, задрахгүй JSON болон оюутан, хичээл, урьдач нөхцөлийн ангиудыг тусгав. Урьдач нөхцөлийн эхний санал нь бүгдийг үзсэн болон дор хаяж нэг нь дутуу гэсэн хоёр ангитай байсан тул огт үзээгүй болон заримыг үзсэн утгуудыг тусад нь төлөөлүүлээгүй. Үндсэн дизайн нь хоосон `coursesTaken` болон хэсэгчилсэн жагсаалтыг тусад нь ашигласан. AI-ийн саналд `studentID`-гүй хүсэлт, мөн оюутан ба хичээл хоёулаа байхгүй хослол нэмэгдсэн бөгөөд эдгээр нь C01–C09-д тусдаа кейсээр тусгагдаагүй. `studentID`-гүй үед `400 ERROR_BAD_REQUEST`, хоёр ID хоёулаа үүсгээгүй үед `200 ERROR_NO_STUDENT` хүлээх нь эх кодын шалгалтын дараалалтай таарсан. Амжилттай хариунд `201`, `OK`, тоон `registrationID` шалгах санал давтан ажиллуулах нөхцөлд зөв байв.
