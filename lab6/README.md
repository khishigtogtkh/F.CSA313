**Оюутны нэр:** С.Хишигтогтох

## A. Category-Partition — POST /transfer

API хүсэлт: `POST /transfer` — `{"from": ID, "to": ID, "amount": NUM, "currency": CODE}`.  
Амжилттай үед `HTTP 201 {"result":"OK"}`, алдаа гарвал тодорхойлолтын дагуу `HTTP 200 {"result":"ERROR_..."}` буцаана.

### A1. Сонголт ба төлөөлөх утгууд

| Параметр | Сонголт | Төлөөлөх утга | Утга |
|---|---|---|---|
| From | Valid | 101 | Оршин байгаа, идэвхтэй данс |
| From | Frozen | 103 | Царцаагдсан данс |
| From | Missing | 9999 | Байхгүй данс |
| To | Valid | 202 | Өөр хүчинтэй данс |
| To | Missing | 9998 | Байхгүй данс |
| To | SameAsFrom | `to = from` | Ижил данс |
| Amount | Normal | 10000 MNT | Эерэг, үлдэгдэл ба лимитэд багтсан |
| Amount | ExactLimit | 50000 MNT | Өдрийн үлдсэн лимиттэй яг тэнцүү |
| Amount | Zero | 0 | Тэг утга |
| Amount | OverBalance | 100001 MNT | Үлдэгдлээс их |
| Amount | OverLimit | 50001 MNT | Өдрийн үлдсэн лимитээс их |
| Currency | Same | MNT | Дансны үндсэн валют |
| Currency | Different | USD | Ханшийн хөрвүүлэлт шаардлагатай |

**Далд орчны нөхцөл:** From дансны төлөв, дансны үлдэгдэл, өдрийн лимитийн нийт хэмжээ/зарцуулалт/үлдсэн хэмжээ, валютын ханш. Жишээ setup: `from.balance=100000 MNT`, `remainingDailyLimit=50000 MNT`, `rate(USD/MNT)=3500` (зөвхөн тестийн таамаг ханш). `OverBalance` үед зөвхөн үлдэгдлийн алдааг тусгаарлахын тулд лимитийг `200000 MNT` болгоно. `Different` валютын үед amount нь USD-ээр өгөгдөх бөгөөд хөрвүүлсэн MNT дүнгээр үлдэгдэл болон лимитийг шалгана. Эдгээр орчны төлөвийг тусдаа PICT параметр болгохгүй, Amount сонголтын утга болон бодит кейсийн setup-д тодорхойлно.

**Currency × Amount-ийн бодит утгууд:** Доорх ханш нь бодит зах зээлийн ханш биш, тогтмол тест өгөгдөл. Бүх дансны үндсэн валют MNT; 101, 202 идэвхтэй, 103 царцаагдсан, 9999/9998 байхгүй. `SameAsFrom` нь сонгосон from ID-г давтана.

| Amount | Same: MNT | Different: USD → MNT | Үлдэгдэл / үлдсэн лимит (MNT) |
|---|---:|---|---|
| Normal | 10000 | 10 → 35000 | 100000 / 50000 |
| ExactLimit | 50000 | 10 → 35000 | Same: 100000 / 50000; Different: 100000 / 35000 |
| Zero | 0 | 0 → 0 | 100000 / 50000 |
| OverBalance | 100001 | 40 → 140000 | 100000 / 200000 |
| OverLimit | 50001 | 15 → 52500 | 100000 / 50000 |

Өдрийн нийт лимитийг 200000 MNT гэж бэлдэж, өмнө зарцуулсан дүнг `200000 − үлдсэн лимит` гэж тохируулна; ингэснээр далд орчны өдрийн хэрэглээ тодорхой болно. `ExactLimit/Different` нь 35000 MNT үлдсэн лимиттэй тусдаа setup ашиглана. Дээрх утга, setup нь A3 болон B-ийн бүх абстракт мөрийг бодит хүсэлт болгох нэг мөр дүрэм болно; Missing дансанд үлдэгдэл, лимит бэлдэхгүй, данс байхгүй алдаа эхэлж шалгагдана.

### A2. `[ERROR]`, `[SINGLE]`, `[IF/property]` хязгаарлалт

| Сонголт | Тэмдэглэгээ | Үндэслэл |
|---|---|---|
| From.Valid | property | Шилжүүлэг хийхийн тулд илгээгч данс идэвхтэй байна |
| From.Frozen | `[ERROR]` | Царцаагдсан данснаас шилжүүлэхгүй |
| From.Missing | `[ERROR]` | Илгээгч данс байхгүй |
| To.Valid | property | Хүлээн авагч хүчинтэй бөгөөд өөр данс |
| To.Missing | `[ERROR]` | Хүлээн авагч байхгүй |
| To.SameAsFrom | `[ERROR]`, `[IF]` | Ижил данс руу шилжүүлэхгүй; `From` оршин байх шаардлагатай |
| Amount.Normal | property | Дүн эерэг, хөрвүүлсэн дүн үлдэгдэл, лимитэд багтана |
| Amount.ExactLimit | `[SINGLE]`, property | Хүчинтэй заагийн утгыг гараар нэг тусгай кейсээр шалгана |
| Amount.Zero | `[ERROR]` | `amount <= 0` |
| Amount.OverBalance | `[ERROR]` | Хөрвүүлсний дараа үлдэгдэл хүрэхгүй |
| Amount.OverLimit | `[ERROR]` | Хөрвүүлсний дараа өдрийн лимит хэтэрнэ |
| Currency.Same | property | Хөрвүүлэлт шаардлагагүй |
| Currency.Different | property | Бэлдсэн ханшаар хөрвүүлэлт хийнэ |

**IF хязгаарлалт (тест сонголтын шийдвэр):**

```text
IF [From] = "Missing" THEN [Amount] = "Normal";
IF [To] = "Missing" THEN [Amount] = "Normal";
IF [To] = "SameAsFrom" THEN [From] <> "Missing";
```

Эхний хоёр IF нь банкны API-ийн заавал дагах бизнесийн дүрэм биш; олон алдааг тусгаарлан тест сонгох зорилготой хязгаарлалт бөгөөд зарим бодит олон алдаатай хүсэлтийг хамралтаас хасна. Гурав дахь нь `SameAsFrom` утгыг оршин байгаа илгээгчийн данстай холбосон семантикийн шийдвэр юм.

**`N → M` тооцоо:**

- Бүрэн олонлог: `3 × 3 × 5 × 2 = 90`.
- IF хязгаарлалтын дараа: `(2×2×5×2) + (2×1×1×2) + (1×2×1×2) = 48`.
- Нэг мөрд хамгийн ихдээ нэг `[ERROR]` байхаар сонгоход: `22` боломжит комбинаци үлдэнэ.
- Тэдгээр 22-ын `ExactLimit` бүхий 6 хувилбараас `[SINGLE]` дүрмээр нэгийг төлөөлүүлж сонговол: `22 − 6 + 1 = 17`.

**Иймээс гараар тест сонгох тооцоо: `90 → 48 → 22 → 17`.** 17 нь IF болон нэг алдааны дүрмийг хангасан 16 комбинаци дээр SINGLE-ийн нэг төлөөллийг нэмсэн тест хүрээний тоо; A3 нь эдгээрээс шаардлагатай ангиудыг сонгосон хүснэгт юм. PICT-ийн pairwise гаралтын мөрийн тоо үүнтэй адил байх албагүй; PICT `ExactLimit`-ийг автоматаар `[SINGLE]` болгохгүй. A3 хүснэгтийн зориуд оруулсан давхар алдааны тусгай кейсүүд нэг алдааг тусгаарлах ердийн `[ERROR]` дүрмийн **нэмэлт** сорил юм.

**Олон алдааны oracle тогтоох таамагласан давуу эрэмбэ:**

`ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO → ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT → ERROR_INSUFFICIENT → ERROR_LIMIT`.

Банкны тодорхойлолт олон алдаа зэрэг илэрвэл ямар хариу буцаахыг заагаагүй тул эхлээд From данс, дараа нь To данс, эцэст нь дүн, үлдэгдэл, лимитийг шалгана гэж **тест дизайны таамаг** тогтоов; үүнийг бодит хэрэгжүүлэлт баталгаажаагүй.

### A3. Спецификацийн хүснэгт

| № | From | To | Amount | Currency | Хүлээгдэх статус, result |
|---:|---|---|---|---|---|
| 1 | Valid | Valid | Normal | Same | `201 OK` |
| 2 | Valid | Valid | Normal | Different | `201 OK` |
| 3 | Valid | Valid | ExactLimit | Same | `201 OK` — SINGLE |
| 4 | Missing | Valid | Normal | Same | `200 ERROR_NO_FROM` |
| 5 | Frozen | Valid | Normal | Same | `200 ERROR_FROZEN` |
| 6 | Valid | Missing | Normal | Same | `200 ERROR_NO_TO` |
| 7 | Valid | SameAsFrom | Normal | Same | `200 ERROR_SAME_ACCOUNT` |
| 8 | Valid | Valid | Zero | Same | `200 ERROR_BAD_AMOUNT` |
| 9 | Valid | Valid | OverBalance | Same | `200 ERROR_INSUFFICIENT` |
| 10 | Valid | Valid | OverLimit | Same | `200 ERROR_LIMIT` |
| 11 | Frozen | Missing | Normal | Same | `200 ERROR_FROZEN` — давхар алдаа, давуу эрэмбэ |
| 12 | Frozen | SameAsFrom | Normal | Different | `200 ERROR_FROZEN` — давхар алдаа, давуу эрэмбэ |

**Тайлбар:** 2-р мөрийн `Normal/Different` бодит утгыг 10 USD = 35000 MNT гэж авна; 12-р мөрийн 10 USD дүн болон 100000 MNT үлдэгдэл, 50000 MNT лимит нь хэвийн боловч Frozen ба SameAsFrom алдаанууд давхар оролцоно. `OverBalance`-д үлдсэн лимитийг 200000 MNT болгож алдааг тусгаарлана. `OverLimit`-д үлдэгдэл 100000 MNT, лимит 50000 MNT байна.

## B. PICT — pairwise covering array

### B1. Browser: 2-way ба 3-way

| Арга | Мөрийн тоо (толгойг оруулаагүй) |
|---|---:|
| Бүрэн олонлог: 3×3×2×2×2×2 | 144 |
| Лекцийн гараар хийсэн 2-way | 9 |
| PICT 2-way: results/browser-2way.txt | 10 |
| PICT 3-way: results/browser-3way.txt | 20 |

PICT-ийн 2-way гаралт 10 мөртэй тул лекцийн 9 мөрөөс 1 мөрөөр олон байна. Greedy алгоритм алхам бүрд хамрагдаагүй олон хосыг хамруулах мөр сонгодог боловч нийт мөрийн хамгийн цөөн тоог заавал олдоггүй. 3-way нь гурван параметрийн боломжит хослол бүрийг хамруулах тул 20 мөр болсон бөгөөд бүрэн олонлогийн 144 мөрөөс 124 мөрөөр цөөн байна.

Дахин ажиллуулах командууд (санамсаргүй `/r` ашиглаагүй):

```bash
cd lab6  # репозиторийн үндсээс
pict browser.model > results/browser-2way.txt
pict browser.model /o:3 > results/browser-3way.txt
```

### B2. Transfer: хязгаарлалт ба сөрөг утга

`transfer-nc.model` нь A1-ийн сонголтуудыг хязгаарлалтгүй агуулна; `transfer.model` нь A2-ын гурван IF-ийг нэмсэн; `transfer-neg.model` нь мөн IF-үүдтэй, долоон ERROR сонголтыг `~` гэж тэмдэглэсэн. Amount.ExactLimit нь эерэг заагийн утга тул negative биш. PICT `[SINGLE]`-ийг автоматаар хэрэгжүүлэхгүй учир ExactLimit хэд хэдэн мөрд орж болно.

```bash
pict transfer-nc.model > results/transfer-nc.txt
pict transfer.model > results/transfer.txt
pict transfer-neg.model > results/transfer-neg.txt
```

| Үзүүлэлт | transfer-nc | transfer | transfer-neg |
|---|---:|---:|---:|
| Нийт мөр (толгойгүй) | 15 | 14 | 18 |
| Happy path: ERROR сонголтгүй | 0 | 2 | 4 |
| Нэг мөрд орсон ERROR-ийн хамгийн их тоо | 3 | 2 | 1 |
| IF хязгаарлалт | Үгүй | Тийм | Тийм |
| `~` negative тэмдэглэгээ | Үгүй | Үгүй | Тийм |

ERROR-ийн тоог From.Frozen/Missing, To.Missing/SameAsFrom, Amount.Zero/OverBalance/OverLimit сонголтын нийлбэрээр тоолов. Happy path-д Normal болон хүчинтэй ExactLimit аль аль нь орно. Хязгаарлалтгүй гаралтад бүх утга хүчинтэй мөр гараагүй: pairwise хамралт нь бүх параметр зэрэг хүчинтэй байх тусгай мөрийг заавал сонгохгүй. IF-тэй хувилбар 2, negative хувилбар 4 happy path мөртэй байна.

`transfer-nc.txt`-ийн 11-р мөр (`Missing / SameAsFrom / OverLimit / Same`) гурван алдааны сонголттой бөгөөд энэ хослолыг A2-ын IF нь хасдаг. From=9999 байхгүй тул A2-ын эрэмбээр `HTTP 200 {"result":"ERROR_NO_FROM"}` хүлээнэ; энэ мөрөөр лимитийн алдааг дангаар батлах боломжгүй. `transfer.txt`-ийн 13-р мөр (`Frozen / Missing / Normal / Different`) хоёр алдаатай бөгөөд `ERROR_FROZEN` нь `ERROR_NO_TO`-г нууна. Ийм олон алдаатай мөр нь тогтоосон давуу эрэмбийг шалгах зорилготой үед тодорхой oracle-той боловч тус бүрийн алдааны боловсруулалтыг тусгаарлахгүй.

`~` хэрэглэхэд нэг мөрд хамгийн ихдээ нэг negative утга орж, ERROR утгууд бие биеэ нуухгүй. Энэ модельд эхний хоёр IF хэрэгтэй хэвээр: ExactLimit нь эерэг утга учир `~Missing + ExactLimit` хослолыг negative дүрэм дангаараа хориглохгүй, харин A2 Missing үед Normal сонгохоор тогтоосон. Гурав дахь IF нь хоёр negative болох Missing ба SameAsFrom-ийг хамтад нь хориглодог тул negative модельд давхар хамгаалалт болж, хассан ч үр дүнгийн зөвшөөрөгдөх орон зай өөрчлөгдөхгүй; A2-той ижил байлгахын тулд үлдээв. Negative модель нь хоорондоо зэрэгцэж болохгүй negative-negative хосыг хамруулахгүй, зөвшөөрөгдөх хосуудыг хамруулна.

### B2.1. PICT гаралтын 3 мөрөөс гаргасан бодит тест кейс

Кейс бүрийг тусдаа, өмнөх кейсийн гүйлгээ нөлөөлөхгүй setup-тай бэлдэнэ. Дансны үндсэн валют MNT; өдрийн нийт лимит 200000 MNT, өмнө зарцуулсан дүн нь нийтээс үлдсэн лимитийг хассан хэмжээ байна. Ханш 1 USD = 3500 MNT нь тогтмол тест өгөгдөл. Эдгээр нь кодгүй лабораторийн тест дизайн бөгөөд бодит API дуудлагын гүйцэтгэлийн тайлан биш.

#### Тест 1 — Happy path

**PICT эх сурвалж:** `results/transfer-neg.txt` файлын 2-р мөр — `From=Valid / To=Valid / Amount=Normal / Currency=Different`.

**Setup:** `from=101` (идэвхтэй), `to=202` (идэвхтэй), `balance=100000 MNT`, `remainingDailyLimit=50000 MNT`, `1 USD=3500 MNT` (жишээ ханш). Хөрвүүлсний дараах amount: `35000 MNT`.

**Оролт:**

```json
{
  "from": 101,
  "to": 202,
  "amount": 10,
  "currency": "USD"
}
```

**Oracle:** `HTTP 201`, `{"result":"OK"}`. Бодит гүйлгээг ажиллуулаагүй: энэ нь спецификацид суурилсан хүлээлт.

#### Тест 2 — Илгээгч байхгүй, нэг negative алдаа

**PICT эх сурвалж:** `results/transfer-neg.txt` файлын 13-р мөр — `From=~Missing / To=Valid / Amount=Normal / Currency=Same`.

**Setup:** 9999 ID-тай данс үүсгэхгүй; `to=202` идэвхтэй MNT дансыг бэлдэнэ. Байхгүй from дансанд үлдэгдэл, лимит оноохгүй бөгөөд эдгээр шалгалтаас өмнө `ERROR_NO_FROM` буцах ёстой. Оролтын дүн 10000 MNT; валют хөрвүүлэх шаардлагагүй.

**Оролт:**

```json
{
  "from": 9999,
  "to": 202,
  "amount": 10000,
  "currency": "MNT"
}
```

**Oracle:** `HTTP 200`, `{"result":"ERROR_NO_FROM"}`. Бодит гүйлгээг ажиллуулаагүй: энэ нь спецификацид суурилсан хүлээлт.

#### Тест 3 — Хөрвүүлсний дараа лимит хэтэрсэн, нэг negative алдаа

**PICT эх сурвалж:** `results/transfer-neg.txt` файлын 10-р мөр — `From=Valid / To=Valid / Amount=~OverLimit / Currency=Different`.

**Setup:** `from=101` (идэвхтэй), `to=202` (идэвхтэй), `balance=100000 MNT`, `remainingDailyLimit=50000 MNT`, `1 USD=3500 MNT` (жишээ ханш). Хөрвүүлсний дараах amount: `52500 MNT`.

**Оролт:**

```json
{
  "from": 101,
  "to": 202,
  "amount": 15,
  "currency": "USD"
}
```

**Oracle:** `HTTP 200`, `{"result":"ERROR_LIMIT"}`. Бодит гүйлгээг ажиллуулаагүй: энэ нь спецификацид суурилсан хүлээлт.

### B3. Хоёр аргын харьцуулалт ба дүгнэлт

Category-Partition нь шаардлагыг сонголт, төлөөлөх утга, хязгаарлалт болгон задлахад тусалсан. Гараар хийсэн A3 хүснэгт нь алдааны анги бүр, SINGLE зааг, давхар алдааны oracle-ийг ил тод харуулдаг давуу талтай. Харин гараар цөөн мөр сонгохдоо бүх зөвшөөрөгдөх хосыг хамарсан эсэхийг батлахад хэцүү. PICT нь модельд зөвшөөрөгдөх хос бүрийг автоматаар хамруулдаг ч загварчлаагүй банкны утга, хүлээгдэх хариуг өөрөө мэдэхгүй. Greedy алгоритм нь хамгийн цөөн мөрийг баталгаажуулахгүй бөгөөд pairwise хамралт нь бүх параметр хүчинтэй happy path мөрийг заавал өгөхгүйг хязгаарлалтгүй гаралт харууллаа. Алдааны сонголтыг энгийн утгаар оруулахад нэг мөрд олон алдаа давхцаж, эхний алдаа бусдыг нуусан. Negative тэмдэглэгээ үүнийг тусгаарласан боловч эерэг ExactLimit-тэй холбоотой IF хамаарал болон гараар сонгох SINGLE дүрмийг бүрэн орлоогүй. Хамгийн их бодол шаардсан хэсэг нь тодорхойлолтод орхигдсон олон алдааны эрэмбийг тогтоох, валют хөрвүүлсний дараах үлдэгдэл ба лимитийн setup-ийг зөрчилгүй бэлдэх явдал байв. Иймээс Category-Partition-оор алдааны семантик, oracle-ийг тодорхойлж, PICT-ээр хосын хамралтыг шалгах нь хоёр аргын давуу талыг хамтад нь ашиглана.
